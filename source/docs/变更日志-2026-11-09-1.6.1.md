# 2026-11-09 变更日志（启动器 1.6.1：更新下载多源重试 + 改名安装兼容）

> 按项目规则记录。本文件对应源码提交 `fix/update-download-fallback` 分支，版本 `1.6.1 / 449`（快照 `450`）。

## 一、本次目标

1. 修复用户反馈：更新时报「下载失败：MeloongCore.dll（远程服务器返回错误: (522)）」。
2. 修复同一用户在源恢复后报「更新清单中没有启动器主程序」。
3. 消除「给 exe 改名」这一类安装引发的连锁问题。

三个问题出自同一条链路：老客户端（≤1.5.7，无 `package` 支持）走 `files` 分支时的下载与主程序识别。

## 二、定位过程

| # | 操作 | 结果与证据 |
|---|---|---|
| 1 | 读用户报错栈 | 两次都落在 `PCL.ModUpdate.UpdateDownloadAndInstallFiles`，说明走的是 `files` 分支，不是 `package` |
| 2 | 逐源实测 `v1.6.0/MeloongCore.dll` | GitHub 直链 302（间歇 000）、`gh-proxy.com` 504、内网 `wg` 206、`ghfast.top` 000、`gh.llkk.cc` 000 |
| 3 | 补充探测替代源 | `ghproxy.net` 200 且 sha256 与清单一致（`a07275b3…5abde`）；`gh-proxy.net` 302 到 `survey-twist.com`，广告跳转，不可用 |
| 4 | 复核主程序识别 | 旧代码 `RelativePath.Equals(IO.Path.GetFileName(PathExe))`；用户安装名 `PCL (NJIT MCL).exe` 与清单 `PCL-NJITMCL.exe` 不匹配，`UpdaterExe` 恒空 |
| 5 | 复核伴生文件 | 旧代码按清单名落盘，改名安装会多出 `PCL-NJITMCL.exe`；`.NET` 只读与 exe 同名的 `.config`，改名后 App.config 静默失效 |

两次报错是同一次更新的两个阶段：第 1 个文件（exe）认不出主程序不报错，第 4 个文件（`MeloongCore.dll`）先死在 522，源恢复后才走到「没有主程序」。

## 三、改动清单（基线：`v1.6.0-source`）

| # | 文件 | 改动 |
|---|---|---|
| 1 | `Modules/ModUpdate.vb` | 新增 `DownloadFromPool / DownloadSingle / IsRetryableDownloadError`；`files`、`package`、旧单文件三条路径统一走同一套下载；连接 8s / 读写 20s 超时；单源重试 2 次（300ms、600ms 退避）；5xx 与超时换源，4xx 放弃该源；内网与中转站强制 `Req.Proxy = Nothing`；主程序先按当前名 / `PCL-NJITMCL.exe` / `Plain Craft Launcher 2.exe` 认，兜底认清单里唯一非 `wg.exe`·`wireguard.exe` 的 exe；新增 `MapProgramFileName` 把主程序、`.exe.config`、`.xml` 映射回当前安装的文件名；失败信息带上源总数与最后一次错误 |
| 2 | `Modules/Base/ModBase.vb` | 新增 `ProgramFileName` / `ProgramBaseName` 只读属性，作为程序身份的唯一来源；版本号 `1.6.1` / `449`（快照 `450`） |
| 3 | `Application.xaml.vb` | 启动时若 exe 被改名，写一条日志；新增 `EnsureCompanionConfig()`：`<exe>.config` 缺失且同目录存在原名那份时复制一份（下次启动生效） |

### 动到的行为边界

- 不改更新协议、不改清单字段、不改 `versionCode` 语义。
- 不改界面，不加设置项，不写注册表，不创建快捷方式。
- `MapProgramFileName` 只处理主程序及其伴生文件；`wg.exe`、`wireguard.exe`、各 `dll` 名字保持清单原名，组件不跟着改名。
