## 二、修了什么

### 1. 退出 MUA 账号后社团生活仍显示已登录

`PageLoginAuthSkin.ExitLogin()` 只清了 `CacheAuthAccess` / `CacheAuthUuid` / `CacheAuthName` 与 `MuaLoggedIn`，
没有结束联机会话。中控设备令牌仍然有效，`ClubLifePanel` 下次拉数据依然拿得到身份，面板一直停在已登录态。

改动：退出时调用 `ModSocial.Logout()`，随后 `FrmLaunchLeft.RefreshPage`，面板立即回到未登录态。

### 2. 头像地址在多处各自拼接

调用点原先自行拼 `/api/launcher/avatar/<id>`，再由 `SocialAvatar` 补主机名；
渲染版本号（`?v=`）只在部分路径上出现，漏一处就会命中客户端 7 天的图片缓存。

改动：新增 `ModSocial.AvatarUrlOf(AccountId)` 作为"按账号取头像"的唯一入口，
内部统一走 `AvatarUrl` 补版本号。所有调用点改为调用它，仓库内不再出现手工拼接。
`AvatarRev` 在服务端改变头像渲染逻辑时递增，客户端 URL 随之变化，缓存自然失效。

### 3. 顺手收口：JSON null 二级取值

`JObject?("key")?("sub")` 在 `key` 为 JSON `null` 时会抛
`Cannot access child value on JValue`。新增 `ModSocial.JChild`，只认 `JObject` 子节点。
`ModClub` 的 `favorite`、`ModJava` 的 `javaVersion` 已改用它。

## 四、发布过程记录

本次 git 通道（`github.com:443`）经出口代理持续 502，`api.github.com` 正常，因此提交改走
GitHub Data API：以远端 `main` 的 tree 为 base，逐文件建 blob、组装 tree、提交后快进 ref。
远端 `main` 因此多出一个内容等价的提交 `59c6b68`（本地对应 `092cd98`）。

### 已修正的两个脚本缺陷

1. **Release 标题被写死**：`release.py` 发布时 PATCH 的标题是 1.6.1 那次留下的字面量，
   导致 `v2.0.2` 的标题显示成 `v1.6.1 · 更新下载多源重试与改名安装兼容`（已手工改正）。
   现在标题一律等于 tag，写错则中止，并在发布后回读校验标题、tag、draft、资产数、资产状态与实际下载。
2. **`target_commitish` 用了远端不存在的 sha**：走 API 推送后本地 HEAD 与远端不同，
   创建 release 时 GitHub 返回 422。现改为优先取 tag 指向的提交。
