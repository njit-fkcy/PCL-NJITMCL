## 十一、1.8.2：MUA 登录页与正版 / MUA 账号权限

- 现象：用户反馈「MUA 登录后头像还是原版、右键刷新无效、切换账号失败、下载整合包提示先登录 MUA」。
- 根因：`PageLaunchLeft` 在 `VersionServerLogin = 0` 时，选中 MUA 就**无条件**进入 `AuthSkin` 头像页，没有检查 `CacheAuthAccess`。未登录也会显示默认头像与切换/退出按钮，造成「已经登录」的错觉；而实际 `MuaLoggedIn` 为 false，所以下载整合包又提示先登录。
- 修复：未登录或已退出时进入 MUA 帐号密码输入页，只有拿到 token 才显示头像页；`PageLoginAuthSkin.ExitLogin` 同步清除 `MuaLoggedIn`，避免退出后仍被当成已登录放行。
- 账号权限：`IsAccountAllowed()` 与 `WgAutoConnect()` 改为按「MUA 已登录，或正版有 `CacheMsV2Access`」判断，不再依赖当前页签的 `LoginType`。正版与 MUA 在下载整合包/存档、连接校内组网上一视同仁（组网分别走 `/api/lease` 与 `/api/lease-ms`）。
- 发布：`1.8.2`/456（快照 457）；主程序 6,099,968 B、sha256 `93ef68ed…`；完整包 6,944,232 B、sha256 `e0e9cd95…`；Release `v1.8.2`（id 440477606，10 资产）；源码提交 `a668585` + tag `v1.8.2-source`；内网 `_launcher/v1.8.2/`；清单 `1.8.2 / 456`。
- 发布过程说明：本机到 `github.com:443` 直连中断，源码改用 **Git Data API**（blob → tree → commit → ref）提交，未走 `git push`；五源验证时 GitHub 直链 000，其余 gh-proxy / ghproxy.net / 内网均为 206。

## 十二、1.8.3：修复更新后 wg 组件丢失

- 现象：用户反馈更新后 `wg.exe` / `wireguard.exe` 消失，校内组网不可用。
